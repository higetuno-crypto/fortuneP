# fortuneP 企画・自走ワークフロー

## 1. このドキュメントの役割
このファイルは、fortuneP を**企画からMVP実装まで、自走型で前進させるための標準ワークフロー**を定義する文書である。

目的は以下。
- 1テーマずつではなく、まとまりのある単位で前進する
- 企画書を起点に、設計・表現・実装へ自然につなげる
- エージェントに何をどう進めさせるかを固定する
- iPhone中心の進行でも迷わず判断できるようにする

この文書は `docs/product-foundation.md` と `docs/autonomous-operation.md` を前提にする。

---

## 2. 基本方針
fortuneP では、単発の思いつきや部分最適ではなく、**企画のまとまり単位で進める**。

つまり、以下の順で進める。

1. 企画書を作る
2. 企画書をもとに、必要な設計文書をまとめて作る
3. 必要なら軽微な実装まで進める
4. 結果を確認し、次スプリントを決める

このワークフローでは、
**「まず企画書を作り、それを起点に自走する」**
ことを基本とする。

---

## 3. 1スプリントの標準手順
### Step 1. テーマを1つ決める
まず、今もっとも前進効果の高いテーマを1つ選ぶ。

例:
- MVP全体の企画書
- UI原則
- 情報設計
- 結果画面設計
- コンテンツスキーマ

### Step 2. 企画書または設計書を作る
選んだテーマに対して、まずは**考えを固定する文書**を作る。

優先する文書例:
- project brief
- feature brief
- UI principles
- information architecture
- content schema

### Step 3. 関連文書をまとめて整備する
必要であれば、関連する2〜5ファイル程度をまとめて整備する。

例:
- 企画書 + UI原則
- 情報設計 + 結果文スキーマ
- 結果画面ブリーフ + 軽微な実装ひな形

### Step 4. 実行結果を短く報告する
最後に、以下を短く報告する。
- やったこと
- 追加 / 更新したファイル
- 判断理由
- 次に進める候補

---

## 4. 企画書起点ワークフロー
fortuneP では、今後の前進は**企画書起点**で行う。

### 基本の流れ
1. 企画書を作る
2. その企画書に必要な設計文書を洗い出す
3. 優先順位の高いものから作る
4. 必要なら実装に入る
5. 結果を確認する

### 企画書に必ず含めること
- 何を作るのか
- なぜ今それを作るのか
- ユーザーに何を感じてほしいか
- MVPにどう効くのか
- 必要な設計ファイルは何か
- 後回しにするものは何か

---

## 5. 感情先行の進め方
fortuneP の企画・設計・実装では、常に**感情目標を先に置く**。

### 必ず先に決めること
- この画面 / 機能で何を感じてほしいか
- どんな余韻を残したいか
- どんなロマンを支えたいか

### その後に決めること
- 何を表示するか
- どの順で読ませるか
- どう操作させるか
- どう演出するか

---

## 6. エージェントへの渡し方
エージェントには、毎回以下の流れで依頼する。

### 基本依頼テンプレート
- 方針文書を読む
- 今もっとも前進効果の高いテーマを選ぶ
- まず企画書または設計文書を作る
- 必要なら関連文書までまとめて整備する
- 結果を短く報告する

### 重要ルール
- 提案だけで止まらない
- まず文書化して判断を固定する
- 1回で広げすぎない
- 2〜5ファイル程度でまとまりを作る
- iPhoneから確認しやすい単位で止まる

---

## 7. fortuneP における標準スプリント
### Sprint A: 企画書
- まずMVP企画書を作る

### Sprint B: UI / 体験設計
- UI原則
- 情報設計

### Sprint C: コンテンツ設計
- 結果文スキーマ
- 用語設計

### Sprint D: 実装の骨組み
- 画面ひな形
- コンポーネント設計

### Sprint E: 質感と演出
- 背景
- 光
- アニメーション
- 余韻づくり

---

## 8. 今の最初の一手
現在の fortuneP では、最初の一手として以下を標準とする。

1. `docs/project-brief.md` を作る
2. そこから必要な設計ファイルを決める
3. 次スプリントで UI原則と情報設計に入る
