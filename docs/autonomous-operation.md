# fortuneP 自走ルール

## 自走判断クイックテーブル

| カテゴリ | 具体例 | 判断 |
|---|---|---|
| docs追加・更新 | 方針書・ガイドライン・設計メモ・UI原則 | ✅ 自走OK |
| READMEの改善 | 概要更新・docs構成反映・現在地の整理 | ✅ 自走OK |
| lib実装（純粋関数） | 占星術計算・ユーティリティ・型定義 | ✅ 自走OK |
| コンテンツ追加 | `content/` 配下のMarkdownファイル | ✅ 自走OK |
| 画面の骨組み実装 | ページひな形・コンポーネントひな形 | ✅ 自走OK |
| ダミーデータ追加 | テスト用サンプル・placeholder | ✅ 自走OK |
| タスク整理 | TODO整理・優先順位並べ替え | ✅ 自走OK |
| 大規模ファイル削除 | 既存ファイルの削除・主要ディレクトリ移動 | 🛑 確認必要 |
| MVP外機能の実装 | 相性診断・課金・会員機能など | 🛑 確認必要 |
| 世界観の大幅変更 | ターゲット変更・コンセプト変更 | 🛑 確認必要 |
| 外部公開・デプロイ | 本番環境への公開・SNS投稿 | 🛑 確認必要 |
| 課金・外部契約 | 有料サービス導入・課金モデル確定 | 🛑 確認必要 |

## 迷ったときの優先順位

| 優先度 | 判断基準 |
|---|---|
| 1 | `docs/product-foundation.md` に合っているか（世界観・占星術の意味） |
| 2 | `docs/mvp-scope.md` に合っているか（今やるべき範囲か） |
| 3 | モバイル体験を良くするか |
| 4 | 体験の余韻やロマンを深めるか |
| 5 | 実装コストに対して効果が高いか |
| 6 | brand voice と astrology model を壊さないか |

---

## 自走時の行動ルール

- **まず実行する** — 提案だけで止まらない
- **実行後に短く報告する** — やったこと・追加ファイル・次の候補を簡潔に
- **不確実なら仮置きで進める** — 「暫定」と明示して前進。完璧を待たない
- **関連するものはまとめて進める** — READMEを更新するならdocs導線整理も一緒に
- **一度に広げすぎない** — MVPを超える拡張は勝手に主軸にしない
- **感情目標のない画面実装はしない** — 先に「何を感じてほしいか」を `docs/ui-principles.md` §1 で確認

## スプリント単位

1テーマに絞り、関連ファイル2〜5個を一度にまとめて進める。途中で確認なしに広げない。

## 実行後の報告フォーマット

```
- やったこと:
- 追加 / 更新したファイル:
- 判断の理由:
- 次に進める候補:
```

## 禁止事項

- 方針文書を無視した独断
- 世界観を壊す雑な量産
- 確認が必要な高影響変更の強行
- 機能性だけを理由に雰囲気と余韻を削り続けること

---

> **合言葉**: 迷ったら前に進める。ただし、壊す可能性が高いときだけ止まる。MVPと世界観を守りながら、実行してから短く報告する。
